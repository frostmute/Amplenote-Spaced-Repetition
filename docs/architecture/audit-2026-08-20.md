# Spaced Repetition Plugin — Code Audit

> Snapshot audit performed against `plugin.js` @ HEAD of
> `frostmute/Amplenote-Spaced-Repetition`.
> Source line count: **1264 lines / 49 KB**.
> Test coverage from latest `lcov.info`: **~44 % lines, ~34 % branches,
> ~67 % functions**.

## Scope

Surface inspected:

- Lifecycle handlers: `appOption.Start Review Session`, `noteOption.Start Review Session`
- Embed surface: `renderEmbed`, `onEmbedCall`
- Markdown pipeline: `_parseCells`, `_extractFlashcardsFromMarkdown`, `_updateFlashcardInLines`, `_saveCardToNote`
- FSRS pipeline: `_createScheduler`, `_updateCardSRS`
- Dashboard pipeline: `_updateDashboard`
- Cross-cutting: counter & index state (`_currentReviewSession`)

## Findings

### Strengths

- **Honest representation of plugin constraints.** The README proactively
  documents the incognito install quirk and Amplenote's
  "aggressive bracket escaping" bug — both of which are real and unfixed at
  the API level. This sets user expectations correctly.
- **Server-side round-trip safety.** `_saveCardToNote` re-reads `note.content()`
  before writing instead of caching the prior parse, which is the right
  pattern in a multi-author environment.
- **Defensive parser.** `_extractFlashcardsFromMarkdown` handles empty cells,
  shifted columns, header strings mixing `<!--…-->` annotations, and quotes
  vs tables — all observed wrinkle classes in Amplenote note exports.
- **No runtime dependencies.** Code is one file with the FSRS algorithm
  inlined; keeps the bundle 49 KB and 260 KB-safe if the embed HTML grows.
- **Visible SR state outside the embed.** The `#srs/due` tag is queryable
  via `app.filterNotes({ tag: 'srs/due' })`, so other tools can integrate
  with the plugin — uncommon for Amplenote plugins.

### Issues

1. **`renderEmbed` is monolithic, ~190 lines of inline HTML**
   `plugin.js:859–997`. Two big HTML literals and a confusing branch ladder
   determine whether to render the in-progress card view vs the completion
   state. Hard to extend with new states (e.g. "lapsed" or "preview").
   - **Risk**: silently fails if a card's `nextReview` ever renders as empty
     string (the `card.question` guard at line 912 is the only fallback).
   - **Fix**: split into `_renderCardHtml(card, progress)` and
     `_renderCompleteHtml(stats)`, return a small router in `renderEmbed`.

2. **Action parsing in `onEmbedCall` covers three signatures**
   (`plugin.js:1000–1027`). The branch ladder tries to handle both
   `callAmplenotePlugin("rate", { rating: 3 })` (object) and
   `callAmplenotePlugin("rate", '{"rating":3}')` (JSON-string) and
   `callAmplenotePlugin('{"action":"rate","rating":3}')` (legacy wrapped).
   - **Risk**: silent acceptance of wrong shapes — if a future Amplenote
     release returns a different tuple, `action` will be `''` and the
     handler silently returns. No warn/log.
   - **Fix**: collapse to a single normalized parser; warn and log when an
     unrecognized shape is seen. Cover with a unit test per supported shape.

3. **Mutable shared state via `this._currentReviewSession`**
   (`plugin.js:1162`). The session object is held across action invocations and
   `renderEmbed`. There's no race protection if a user fires the
   `Start Review Session` app option while a sidebar embed is open — the
   second call overwrites `_currentReviewSession` while the first one's
   embed is still active.
   - **Risk**: cross-session pollution, counts being mis-attributed to a
     newer session.
   - **Fix**: namespace sessions by a session UUID stored alongside
     `_currentReviewSession` and verify on re-entry.

4. **`_updateDashboard` re-renders **every** session**
   (`plugin.js:1062`). The full Markdown for the dashboard is rewritten each
   time, even when only the totals changed. The hidden `<!--STATS:…-->`
   comment is the only recovery path if a write fails midway.
   - **Risk**: if `app.replaceNoteContent` returns silently after a partial
     failure, the dashboard note can be left corrupted. No transactional
     safety.
   - **Fix**: write to a temp buffer in the embed state and validate the
     rendered string contains a parseable `<!--STATS:…-->` before applying;
     rollback on validation failure.

5. **`_collectDueCards` calls `app.filterNotes` per tag, then per note**
   (`plugin.js:510–557`). With many tags / many notes this scales O(tags ×
   notes × flashcards). Each fetch is whole-note content read; for thousands
   of cards this becomes the dominant load.
   - **Risk**: progressive slowdown as users accumulate notes.
   - **Fix**: precompute a tag→note cache once per session, deduplicate note
     lookups, and lazy-fetch content only when cards are needed.

6. **No automatic essay / multiple-choice flashcard detection**
   The plugin implicitly assumes Q/A is exactly two columns. Tables with
   more columns are silently dropped.
   - **Risk**: user confusion when defines a deck with extra columns; no
     error message.
   - **Fix**: warn once if a table has more than 2 columns AND isn't named
     via a recognized header convention (e.g. `Question` / `Answer` /
     `SRS_DATA` known columns ignored).

7. **`_saveCardToNote`'s identifier fallback for "corrupted rows"**
   (`plugin.js:1190–1193`) matches cards by `c.answer === card.question` —
   that's a fragile identity check. If a user has two Q-A flashcards with
   swapped Q/A content, they'd both match the same card.
   - **Fix**: include lineIndex in the candidate set and write a unit test
     for the swap-recovery path.

8. **Embed HTML escapes backslashes but also `[`/`]`**
   (`plugin.js:382–389`). The `_escapeHtml` function does double duty: HTML
   escape and Markdown bracket cleanup. The two jobs aren't separable,
   making it impossible to inject raw code fragments that contain backticks.
   - **Fix**: split into `_escapeHtml` and `_stripMarkdownEscapes`; tested
     separately.

9. **No CI for bundle size regression.** Plugin note can't grow silently
   beyond 260 KB once the FSRS math or embed HTML is expanded.
   - **Fix**: a `prebuild` `wc -c` check failing at 220 KB.

10. **Settings UX gap.** `app.settings['Daily Review Limit']` is read
    directly but never validated against `NaN`/`0`/negative values inside
    `noteOption` (`plugin.js:610`). The validate-once guard exists in
    `_collectDueCards` but not in the per-card free-tier path.
    - **Fix**: extract `_getDailyLimit(app)` returning a clamped positive
      integer.

11. **Readme has literal `\n` artefact strings.**
    `README.md:124-126` includes `\n\n` that render as escaped text, not as
    section breaks. The phase-3 audit didn't fix this.
    - **Fix**: convert the backslash-n runs into real newlines and re-flow
      the section.

### Lower-priority / nice-to-have

- `_createScheduler` weights array (`plugin.js:415–418`) is FSRS-5 canonical,
  but not documented in the README as "from open-spaced-repetition v5 ref
  impl". A one-line attribution closes the audit trail.
- The `simulation.js` "test" is more of a manual smoke than an assertion —
  convert at least the dashboard update step into a jest assertion.
- Add an explicit contract test: export shape (`appOption`, `noteOption`,
  `renderEmbed`) is non-empty and stable.

## Test-coverage delta vs prod behavior

The `integration.test.js` (4 cases) and `parse.test.js` (8 cases) cover the
two most data-driven functions. The `simulation.js` script exercises the
review loop but isn't a Jest test. **No tests at all exist for**:

- `renderEmbed` HTML output (string-level)
- `onEmbedCall` action parsing / legacy wrapping
- `_updateDashboard` failure paths
- `_collectDueCards` sort orders (`Random`, `Easiness (Hardest First)`)
- `_runFreeTierPromptSession` cancel-resume semantics

Adding these would lift coverage past ~70 % lines with a small number of
well-chosen fixtures.

## Risk score (informal)

| Area | Severity | Notes |
| --- | --- | --- |
| Embed HTML regression | High | Single source of truth, ~190 lines, no fallback test |
| Session state races | High | Cross-session pollution potential |
| Dashboard corruption | Medium | Failure mode is silent |
| Card identity fragility | Medium | Edge case but recoverable |
| Bundle size drift | Low | Currently 49 KB, far under limit |
| Missing settings validation | Low | Currently loop-local, narrow blast radius |

## Recommendations (in priority order)

1. **Refactor `renderEmbed` into <= 2 helpers.** Highest leverage — biggest
   failure surface.
2. **Lock in `onEmbedCall` contract.** Normalize once, log on unknown
   shape.
3. **Session namespacing.** Distinct UUID per `Start Review Session`,
   validated on every embed render.
4. **Add Jest tests for**: `renderEmbed` happy path, `onEmbedCall` rate
   cycle, `_collectDueCards` sort variants, dashboard failure rollback
   detection.
5. **Add a `prebuild` size check** failing above 220 KB raw.
6. **README cleanup pass**: convert literal `\n\n`, link the FSRS weights to
   the open-spaced-repetition v5 reference implementation.
7. **Split `_escapeHtml`** into HTML escape vs Markdown-strip functions.

## Status snapshot

The 2026-06-26 `initial-audit.md` flagged the monolithic file, sub-3 test
count, and missing lint — all addressed (lint added, tests expanded to two
spec files, FSRS verified). The audit above targets the *next* layer: the
embed surface, the embed/SDK contract, and runtime robustness under load.
